# spec-dev

**规范驱动开发（Spec-Driven Development）** —— 将开发任务拆解为需求、设计、任务、实现和验证的 Skill，让改动可确认、可追踪、可验收。

适用于新功能、跨模块重构、接口或数据结构变更、安全或权限调整，以及需要多步实现或用户评审的任务。简单修正和咨询类请求通常不必生成 Spec，用户明确要求时除外。

## 安装

克隆到 Claude Code 技能目录：

```bash
# macOS / Linux
git clone https://github.com/libo1248/spec-dev.git \
  ~/.claude/skills/spec-dev
```

```powershell
# Windows
git clone https://github.com/libo1248/spec-dev.git `
  "$env:USERPROFILE\.claude\skills\spec-dev"
```

## 使用

```text
/spec-dev
```

也可以直接描述任务：

```text
使用 spec-dev，为用户登录功能生成需求、设计和任务拆解。
```

Skill 会先检查项目规则、工作区和验证命令，再说明选择的模式。需要完整流程时，可明确要求“使用完整模式”。默认不会覆盖已有修改，也不会执行 Git commit、push、发布或创建 PR。

## 两种模式

| 模式 | 适用条件 | 产物与确认 |
|------|----------|------------|
| **完整** | 新功能、跨模块重构、接口/数据结构/Schema、安全或权限变更；或用户明确要求 | `requirements.md`、`design.md`、`tasks.md`，分别确认 |
| **轻量** | 范围单一、低风险、不涉及完整模式条件的任务 | 合并为 `spec.md`，编码前一次整体确认 |

轻量模式只合并规格编写和确认，仍保留验收标准、任务追溯、测试与最终验收。不确定风险时使用完整模式。

## 流程概览

1. **执行前检查**：读取规则、保护已有修改、识别验证命令、澄清需求。
2. **需求规格**：明确目标、范围、非目标和验收标准（AC），等待确认。
3. **架构设计**：定义实现方案和验证策略，等待确认。
4. **任务拆解**：列出任务、依赖和验证方式，等待确认。
5. **实现与验证**：逐 Task 编码、测试和修复，每个 Task 最多修复 3 次，超限停止并报告。
6. **最终验收**：全量回归、逐项验收 AC、同步文档并汇报结果。

确认支持“继续”“这个方案可以”等明确接受表达。修改意见或部分确认不会自动推进阶段。轻量模式在需求、设计和任务编写完成后统一确认。

## 产物与任务示例

规格统一保存在 `specs/YYYYMMDD-功能名/` 下：完整模式使用三个独立文件，轻量模式使用 `spec.md`。已有同一任务的规格优先读取并复用，不直接覆盖。

```md
- [ ] T-001: 增加登录接口
  - Requirements: AC-01, AC-02
  - Design: §3.1, §4.2
  - Depends on: None
  - Verify: `npm test -- auth`
  - Scope: API handler、参数校验和单元测试
```

示例命令仅演示格式，实际验证使用项目已有命令。任务编号保持稳定，只有满足实现和验证条件才标记完成；延期或取消需要用户确认。
